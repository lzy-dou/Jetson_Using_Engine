1. 环境概述

1.1 硬件与系统

目标平台为 NVIDIA Jetson Orin，运行 Ubuntu 22.04 (Jammy) 系统，搭载 JetPack 6.2 (r36.4)，对应 CUDA 12.6。目标是编译一个 C++ 程序，用于加载并运行 TensorRT 推理引擎（.engine 文件），模型为 YOLOv8n-cls 分类模型和 YOLOv8 检测模型。

1.2 问题总览

2. 问题一：libcudla.so.1 缺失（链接阶段）

2.1 现象

C++ 编译时，链接阶段报错：libnvinfer.so 依赖 libcudla.so.1，但系统中找不到该库。具体错误为 undefined reference to cudlaCreateDevice@libcudla.so.1 等一系列 cudla* 符号未定义。

2.2 根因分析

Jetson 平台上 DLA（Deep Learning Accelerator）相关的库有两个不同的 API：

库名API 类型符号前缀来源
libnvcudla.soDLA Driver APIcudlaDrv*Tegra BSP（系统自带）
libcudla.so.1cuDLA Runtime APIcudla*CUDA Toolkit（需安装）

TensorRT 10.3 的 libnvinfer.so 依赖的是 cuDLA Runtime API（cudla* 符号），但系统只安装了 DLA Driver API（cudlaDrv* 符号）。两者符号完全不同，不能互相替换。

2.3 尝试过的失败方案

  • 方案一：创建软链接 libcudla.so.1 -> libcuda.so.1。失败，因为 libcuda.so 导出的是 cu* 前缀的 CUDA Driver API 符号，与 cudla* 完全不同。
  • 方案二：创建软链接 libcudla.so.1 -> libnvcudla.so。失败，因为虽然指向了 DLA 库，但符号前缀不匹配（cudla* vs cudlaDrv*）。
  • 方案三：用 patchelf 修改 libnvcudla.so 的 SONAME 为 libcudla.so.1。ldconfig 能识别了，但链接时仍然报 undefined reference，因为符号根本不存在。

2.4 最终解决方案

安装 JetPack 仓库的 cuda-libraries-12-6 包，其中包含 libcudla-12-6 子包，提供了正确的 cuDLA Runtime API（cudla* 符号）：

sudo apt install cuda-libraries-12-6

安装后验证：

ls /usr/local/cuda-12.6/targets/aarch64-linux/lib/ | grep cudla
# 应输出: libcudla.so  libcudla.so.1  libcudla.so.1.0.0

ldconfig -p | grep cudla
# 应输出: libcudla.so.1 => /usr/local/cuda/targets/aarch64-linux/lib/libcudla.so.1

nm -D /usr/local/cuda-12.6/targets/aarch64-linux/lib/libcudla.so.1 | grep cudla
# 应输出: cudlaCreateDevice  cudlaDestroyDevice  cudlaModuleLoadFromMemory 等
关键认知：libnvcudla.so 和 libcudla.so 是两个完全不同的库，虽然都与 DLA 相关，但 API 不同、符号不同、用途不同。不能通过软链接或修改 SONAME 的方式互相替代。必须安装正确的包来获取所需的 API。

3. 问题二：CUDA 版本冲突（11.5 vs 12.6）

3.1 现象

执行 sudo apt install nvidia-jetpack 时报依赖冲突错误：nvidia-jetpack-dev 依赖 nvidia-cuda-dev (= 6.2.1+b38) 但是 11.5.1-1ubuntu1 正要被安装。

3.2 根因分析

系统配置了两个 CUDA 软件源，版本完全不兼容：

来源包名CUDA 版本含 libcudla.so
Ubuntu Tsinghua 镜像 (jammy)nvidia-cuda-toolkit11.5否（桌面版）
NVIDIA JetPack 仓库 (r36.4)nvidia-cuda12.6是（Jetson 版）

硬件是 Jetson Orin (t234) + JetPack 6.2 (r36.4)，正确对应的是 CUDA 12.6，不是 11.5。Ubuntu 仓库的桌面版 CUDA 包根本不包含 Jetson 专有的 DLA 库。

3.3 解决方案

第一步：卸载 Ubuntu 仓库的 CUDA 11.5 包

sudo apt remove --purge nvidia-cuda-toolkit nvidia-cuda-dev \
  nvidia-cuda-gdb nvidia-cuda-toolkit-doc nvidia-cuda-toolkit-gcc
sudo apt autoremove --purge

第二步：解决 nvidia-container 版本冲突

# 降级 container 包到 JetPack 要求版本
sudo apt install \
  nvidia-container-toolkit-base=1.16.2-1 \
  libnvidia-container-tools=1.16.2-1 \
  nvidia-container-toolkit=1.16.2-1 \
  libnvidia-container1=1.16.2-1

第三步：安装 JetPack 的 CUDA 12.6

sudo apt install nvidia-jetpack

3.4 长期防范

为避免 Ubuntu 仓库的 CUDA 包再次干扰 JetPack 包，创建 apt pin 配置：

sudo tee /etc/apt/preferences.d/block-ubuntu-cuda <<'EOF'
Package: nvidia-cuda-toolkit nvidia-cuda-dev nvidia-cuda-gdb \
  nvidia-cuda-toolkit-doc nvidia-cuda-toolkit-gcc
Pin: release o=Ubuntu
Pin-Priority: -1
EOF
sudo apt update

5. 问题四：PyTorch 版本冲突（1.8 vs 2.5）

5.1 现象

加载 .pt 模型时报错：AttributeError: Can't get attribute 'InterpolationMode' on <module 'torchvision.transforms.functional'>。

5.2 根因分析

系统通过 apt 安装的是 PyTorch 1.8.0a0（包名 libtorch1.8），太旧。YOLOv8 需要的 ultralytics 要求 PyTorch 1.8 以上且 torchvision 0.9.0 以上。旧版 torchvision 0.8.0a0 缺少 InterpolationMode 类。

5.3 解决方案

5.3.1 卸载旧版 PyTorch

sudo apt remove --purge libtorch-dev libtorch-test libtorch1.8:arm64
sudo apt autoremove --purge

5.3.2 安装 NVIDIA Jetson 官版 PyTorch 2.5

Jetson 上的 PyTorch 必须使用 NVIDIA 官方编译的 wheel，不能用 pip 装标准版（标准版不带 Jetson 的 CUDA 支持）：

pip3 install https://developer.download.nvidia.com/compute/redist/jp/v61/pytorch/torch-2.5.0a0+872d972e41.nv24.08.17622132-cp310-cp310-linux_aarch64.whl

5.3.3 设置环境变量

PyTorch 需要找到 CUDA 库，必须设置 LD_LIBRARY_PATH：

export LD_LIBRARY_PATH=/usr/local/cuda-12.6/targets/aarch64-linux/lib:$LD_LIBRARY_PATH

# 写入 bashrc 永久生效
echo 'export LD_LIBRARY_PATH=/usr/local/cuda-12.6/targets/aarch64-linux/lib:$LD_LIBRARY_PATH' >> ~/.bashrc
source ~/.bashrc

5.3.4 从源码编译 torchvision 0.20.0

Jetson 上没有 torchvision 的预编译 wheel，必须从源码编译：

# 安装编译依赖
sudo apt install -y libjpeg-dev libpng-dev libavcodec-dev libavformat-dev libswscale-dev

# 下载源码
cd ~
git clone https://github.com/pytorch/vision
cd vision
git checkout v0.20.0

# 设置编译环境变量
export BUILD_VERSION=0.20.0
export TORCH_CUDA_ARCH_LIST="8.7"
export FORCE_CUDA=1
export CUDA_HOME=/usr/local/cuda
export MAX_JOBS=2  # 限制并发数防止内存不足

# 编译安装
python3 setup.py install --user

# 验证
python3 -c "import torch; import torchvision; print('torch:', torch.__version__, 'torchvision:', torchvision.__version__)"

5.3.5 降级 numpy

PyTorch 2.5 需要 numpy 1.x，不兼容 numpy 2.x：

pip3 install "numpy<2" --force-reinstall

6. 问题五：TensorRT 引擎序列化不兼容

6.1 现象

Python 成功导出 .engine 文件后，C++ 加载时报错：Serialization assertion plan->header.magicTag == rt::kPLAN_MAGIC_TAG failed. Trying to load an engine created with incompatible serialization version.

6.2 根因分析

Python 使用的 tensorrt 模块和 C++ 链接的 libnvinfer.so 虽然版本号都是 10.3.0，但内部序列化格式不兼容。可能原因：

  • Python 的 tensorrt 包编译时的配置和系统 libnvinfer-dev 不同
  • 或者 ultralytics 内部调用了不同的 TensorRT API 版本

6.3 验证过程

# 确认 Python tensorrt 来源
python3 -c "import tensorrt as trt; print(trt.__file__)"
# 输出: /usr/lib/python3.10/dist-packages/tensorrt/__init__.py

# 确认版本一致
python3 -c "import tensorrt; print(tensorrt.__version__)"  # 10.3.0
dpkg -l | grep libnvinfer  # 10.3.0.30-1+cuda12.5

# 即使来源和版本都一致，C++ 仍然无法加载 Python 导出的 engine

6.4 解决方案：用 C++ 从 ONNX 构建 Engine

编写一个 C++ 工具 build_engine，直接从 ONNX 文件构建 TensorRT 引擎。因为 build_engine 和 trt_infer 链接的是同一个 libnvinfer.so，序列化格式 100% 兼容。

6.4.1 build_engine.cpp 核心代码

// 1. 创建 builder 和 network
nvinfer1::IBuilder* builder = nvinfer1::createInferRuntime(logger);
auto network = builder->createNetworkV2(
    1U << static_cast<uint32_t>(nvinfer1::NetworkDefinitionCreationFlag::kEXPLICIT_BATCH));

// 2. 解析 ONNX
auto parser = nvonnxparser::createParser(*network, logger);
parser->parseFromFile(onnx_path, severity);

// 3. 配置 builder
auto config = builder->createBuilderConfig();
config->setMemoryPoolLimit(nvinfer1::MemoryPoolType::kWORKSPACE, 2ULL << 30);
if (use_fp16 && builder->platformHasFastFp16()) {
    config->setFlag(nvinfer1::BuilderFlag::kFP16);
}

// 4. 构建并保存
auto serialized = builder->buildSerializedNetwork(*network, *config);
std::ofstream file(engine_path, std::ios::binary);
file.write(reinterpret_cast<const char*>(serialized->data()), serialized->size());

6.4.2 使用方式

./build_engine input.onnx output.engine fp16
关键认知：在 Jetson 上，Python 导出的 engine 和 C++ 加载的 engine 可能不兼容，即使版本号相同。最可靠的方式是用 C++ 从 ONNX 直接构建 engine，确保构建和推理使用同一个库。

7. 问题六：动态 Shape 处理

7.1 现象

ONNX 模型的输入 shape 是动态的 [-1, 3, -1, -1]（batch、高度、宽度都可变），导致两个问题：

  • 构建 engine 时报错：Network has dynamic or shape inputs, but no optimization profile has been defined
  • 推理时 input_size 计算为 -1，分配超大 vector 导致崩溃：cannot create std::vector larger than max_size

7.2 解决方案

7.2.1 build_engine.cpp：添加 Optimization Profile

为动态输入定义 min/opt/max 尺寸范围：

nvinfer1::IOptimizationProfile* profile = builder->createOptimizationProfile();

// 检测动态维度
bool is_dynamic = false;
for (int j = 0; j < dims.nbDims; j++) {
    if (dims.d[j] == -1) { is_dynamic = true; break; }
}

if (is_dynamic) {
    nvinfer1::Dims d_min(dims), d_opt(dims), d_max(dims);
    d_min.d[0] = 1; d_opt.d[0] = 1; d_max.d[0] = 1;
    d_min.d[2] = 320; d_min.d[3] = 320;   // 最小尺寸
    d_opt.d[2] = 640; d_opt.d[3] = 640;   // 最优尺寸
    d_max.d[2] = 960; d_max.d[3] = 960;   // 最大尺寸

    profile->setDimensions(input->getName(), nvinfer1::OptProfileSelector::kMIN, d_min);
    profile->setDimensions(input->getName(), nvinfer1::OptProfileSelector::kOPT, d_opt);
    profile->setDimensions(input->getName(), nvinfer1::OptProfileSelector::kMAX, d_max);
}
config->addOptimizationProfile(profile);

7.2.2 trt_infer.cpp：推理前设置实际输入尺寸

推理前必须调用 setInputShape() 设置实际输入尺寸，否则输出 shape 仍为 -1：

// 设置实际输入尺寸
nvinfer1::Dims actual_input_dims = input_dims;
actual_input_dims.d[0] = 1;
actual_input_dims.d[1] = 3;
actual_input_dims.d[2] = INPUT_SIZE;  // 640
actual_input_dims.d[3] = INPUT_SIZE;  // 640
context->setInputShape(input_name.c_str(), actual_input_dims);

// 设置后获取实际输出 shape
output_dims = context->getTensorShape(output_name.c_str());

// 根据实际尺寸分配缓冲区
input_size = 1 * 3 * INPUT_SIZE * INPUT_SIZE;
output_size = 1;
for (int j = 0; j < output_dims.nbDims; j++) output_size *= output_dims.d[j];

cudaMalloc(&d_input, input_size * sizeof(float));
cudaMalloc(&d_output, output_size * sizeof(float));

7.3 输入尺寸注意事项

Engine 导出时输入尺寸就固定了。如果导出时是 64x64，推理时必须用 64x64。要改输入大小必须重新导出 engine。动态 shape 的 engine 支持范围内任意尺寸（必须是 32 的整数倍），但每次推理前必须调用 setInputShape() 设置实际尺寸。

9. 关键经验教训

9.1 只用 JetPack 仓库的包

Jetson 平台只能使用 JetPack 仓库 (r36.4) 的包，不能使用 Ubuntu 仓库的桌面版包。两者虽然版本号可能接近，但库的符号、ABI、序列化格式都可能不同，混装必然出问题。特别是 CUDA 包，Ubuntu 版不含 Jetson 专有的 DLA 库。

9.2 libcudla.so vs libnvcudla.so

这是两个完全不同的库：libnvcudla.so 是 DLA Driver API（cudlaDrv* 符号），libcudla.so.1 是 cuDLA Runtime API（cudla* 符号）。TensorRT 需要 Runtime API。不能通过软链接或 patchelf 互相替代，必须安装正确的包（cuda-libraries-12-6 中的 libcudla-12-6）。

9.3 PyTorch 必须用 Jetson 官版

标准版 pip install torch 不带 Jetson 的 CUDA 支持。必须从 NVIDIA 官方下载 Jetson 专用 wheel。torchvision 没有预编译版本，必须从源码编译，编译时设置 TORCH_CUDA_ARCH_LIST="8.7"（Orin 的计算能力）。

9.4 Engine 构建和加载必须用同一个库

Python 导出的 engine 和 C++ 加载的 engine 可能不兼容，即使版本号相同。最可靠的方式是用 C++ 从 ONNX 直接构建 engine，确保构建和推理使用同一个 libnvinfer.so。

9.5 动态 Shape 需要额外处理

ONNX 导出时如果使用 dynamic=True，输入 shape 会是 [-1, 3, -1, -1]。TensorRT 构建时需要定义 optimization profile（min/opt/max 尺寸），推理时需要调用 setInputShape() 设置实际尺寸。如果不需要动态输入，导出 ONNX 时设置 dynamic=False 可以避免这些问题。

9.6 排查问题的通用方法

  • 用 nm -D 检查库导出的符号
  • 用 readelf -d 检查 SONAME
  • 用 ldd 检查库的依赖是否解析
  • 用 ldconfig -p 检查库是否在缓存中
  • 用 apt-cache policy 检查包来源和版本
  • 用 dpkg -L 检查包安装了哪些文件
  • 用 find 全局搜索文件位置
